Этот файл — единственный источник правды о том, что сделано.
Начало сессии с ассистентом: прислать `cat docs/PLAN.md`.
Конец сессии: обновить отметки и «Журнал сессий», закоммитить.

## Назначение
Подбор товаров по заявкам клиентов. Менеджер вставляет текст письма или таблицу
из Excel. Приложение находит товары (словарь синонимов из Access, артикулы,
наименования), считает цену по типу цен клиента, распределяет резерв по остатку
и готовит выгрузку в 1С.

## Стек
Python 3, PostgreSQL, SQLAlchemy (async), миграции в migrations/versions,
pydantic-settings, uv. Вход: OIDC; AUTH_MODE=dev только при APP_ENV=dev.
Веб-фреймворк и OIDC-провайдер: уточнить.

- Сервер: в одной ЛВС с 192.168.0.251. Сетевые папки монтируются ТОЛЬКО НА ЧТЕНИЕ
  в /mnt/rossvik/ftp1 и /mnt/rossvik/ftp (cifs + systemd automount).

## Принятые решения (не пересматривать без причины)
1. По умолчанию APP_ENV=prod: забытая настройка не ослабляет защиту.
2. DatabaseSettings отдельно от Settings: инструментам не нужны секреты входа.
3. «Код в 1С» в distr.xlsx обязателен: по нему узнаём товар со сменившимся артикулом.
4. Ценовые группы задаются в админке, а не через distr. Колонка «ЦеноваяГруппа» необязательна.
5. Поиск объединяет словарь, артикул и наименование. Несколько активных товаров —
   строка неоднозначна, выбирает менеджер. Снятые показываем, только если нет активных.
6. Порядок кандидатов — как на сайте («Сортировка на сайте»).
7. Резерв распределяется по строкам заявки сверху вниз.
8. Нулевая или пустая базовая цена никогда не уходит в 1С.
9. Выгрузки читаем со снимка (копия, не менявшаяся во время копирования).
10. Импорт по таймеру не выполняется, если он снимает слишком много товаров
    или удаляет слишком много клиентов. Из админки — только с подтверждением.
